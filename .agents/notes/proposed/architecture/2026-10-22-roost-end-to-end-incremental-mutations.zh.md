# Roost 端到端增量变更

Status: proposed
Translation: current

[English](2026-10-22-roost-end-to-end-incremental-mutations.md)

## 摘要

Native 的文本追加已经是增量操作，但 Lody 每次提交仍复制、扫描完整正文，并在本地
创建消息后重新读取整个分支窗口。本次让语义追加计划贯穿验证、持久化与私有投影安装，
并使用 SDK 证明的目录变更。在固定的 Linux 持久化长回复用例中，分块写入 p95 从
26.30 降到 11.98 ms；多消息用例的创建 p95 从 103.01 降到 68.34 ms。
磁盘体积没有实质变化，多消息路径仍慢于 Loro。

## 问题与决策

基线为 Lody `f06b820f3`、Roost `ff1a639`，包含
[原子检查点](2026-10-22-roost-atomic-content-checkpoints.zh.md)及
[此前的投影优化](2026-10-22-roost-owner-incremental-projection.zh.md)。
独立合成探针在旧正文 0/256 KiB/1 MiB 时测到 Native 追加 p50 为
0.178/0.167/0.172 ms，Lody/Roost 则由 1.621 增至 4.770 ms。
Native 探针省略应用收据、索引、控制文档持久化及分发，只能定位额外开销，不能承诺
完整应用能达到该延迟。

共享 reducer 现在生成不可变变更计划及显式文本追加意图，保留逐事件处理顺序、快照/
重叠去重、跨分块内部提示标记与 thinking/plan 标签语义。私有的有限后缀分析避免重新
扫描普通干净文本；复杂文本沿用原解析器。精确源值检查会在调用方修改内容后失效，
已有损坏标量的修复或拒绝语义也保持一致。

Lody 在串行写入范围内借用私有快照，验证所有新写入，只复制变化路径，再通过原有
逻辑投影器安装，省去额外完整复制。这样仍保留规范属性顺序、覆盖层、默认字段与未知
存储字段。公共读取继续返回独立副本，小型 model 摘要跨入控制文档前也会复制。

Roost 负责检查点及分支证据。复用的检查点前置条件仍在每次事务中比较；只有 Native
证明未提交的 stale 才失效并刷新一次。目录变更只证明已确认本地线性追加的成员关系，
不证明旧正文的新鲜度。Native 元数据、实际事件区间、generation 及最终发布检查仍控制
安装。分叉、远端交错、不完整页及结果不确定时继续权威恢复。Rust/Native 运行时代码
没有变化。稳定本地创建的诊断调用数由 237 降到 97，这不是互联网往返延迟测量。

用户授权以可观察行为及正确性不变为前提；遇到未解决的保证变化需停下来讨论。
本次不包含旧格式读取、迁移、裁剪、降低持久化保证、发包或部署。每块重建完整正文、
每次已知本地追加后重读窗口的方案被放弃，因为已有事务证据足以支持私有复用。

## 验证与测量边界

[统一验证流程](../../../docs/roost-validation.md)维护可复用的依赖准备、套件选择、固定
benchmark 命令、指标口径与失败处理。本轮持久化合成脚本原本仅存在于临时目录，现在
连同显式配置放进 `apps/cli/benchmarks`，默认 CI 不执行。反复遇到的 SDK/链接准备
问题应更新该文档，不应再创建一套临时流程。

Linux x64、Node 24.22、2 vCPU，前后使用同一个 Native 二进制，SQLite WAL/FULL，
每个动作均持久化控制文档。基线/候选按 A–B–B–A 运行；Loro 使用候选版共享语义，
仅作一轮参照。下表为各轮 p95 的中位数，单位 ms；增量消费者读取交错执行、单独计时。

| 用例 / 指标                          |   基线 |  候选 |  Loro |
| ------------------------------------ | -----: | ----: | ----: |
| 100 轮、2,000 × 256 B 分块：写入 p95 |  12.50 | 11.23 |  4.89 |
| 同上：创建消息 p95                   | 103.01 | 68.34 |  5.17 |
| 单回复、1,000 × 1 KiB 分块：写入 p95 |  26.30 | 11.98 | 13.22 |

两种用例每条 assistant 都保留 16 KiB 合成工具输出。长回复写入 CPU 由 14.92 降至
6.27 秒；完整验证前采样的进程峰值 RSS 由 613 降至 474 MiB。此值包含 runner/控制层，
不是 Roost 独占内存。多消息总数据库约 14.38 MB，Loro 为 2.90 MB；长回复约 6.56 MB，
Loro 为 1.54 MB。这不足以证明超长会话远快于 Loro，固定 SDK/Worker 开销与保留日志
放大仍未解决。

30 个写入/重开/分页阶段全部通过；完整文本及工具输出、收据重试、跨后端规范业务
摘要、重开后的完整摘要与 18 次关闭进程后的 SQLite 检查全部通过。运行时源码哈希
与候选一致，研究工作区的源码及依赖链接已全部恢复。

使用匹配本地 SDK 的 Lody 根 `pnpm check` 及格式化通过；Native 59 例、SDK 相关
套件（Chromium/Node 101、WebKit 63）通过。最初完整并行 SDK 测试遇到父测试超时，
取消的子测试不计为通过。Rust fmt/clippy 通过；根串行测试在未修改的 `rs3_link`
回环测试报 `Transport(Unavailable)` 后停止，该例隔离重跑通过，不将原执行报告为
完整 Rust 测试全绿。新增手动入口的发现检查及 lint 通过，只选择持久化 benchmark；
文档和格式检查覆盖统一流程。

原始合成样本/哈希位于验证工作区 `incremental-mutations-20261022/linux-results.json`，
不提交用户数据。本次草稿叠在 Lody #1811 及 Roost #25 后的对应 SDK 变更上，仍需要
协调 Roost 发包后更新真实依赖指针；已发布的 0.2.0 SDK 不提供新增目录 API。

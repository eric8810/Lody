# Roost 端到端增量变更

Status: proposed
Translation: current

[English](2026-10-22-roost-end-to-end-incremental-mutations.md)

## 摘要

Native 文本追加已经是增量的，但 Lody 在提交前后仍复制完整消息或状态正文，
并重新读取已加载的历史。本次将共享语义层的变更计划贯穿验证、Native 内容操作和
私有投影安装，并使用 SDK 证明过的目录转换。范围包括标签、工具、结束动作和恢复
后的状态更新，也包括普通文本追加。公开读取的所有权、持久化确认和权威恢复保持
原有约束；性能结论仅适用于下文成对测量的工作负载。

## 问题与决策

本次接续[原子检查点工作](2026-10-22-roost-atomic-content-checkpoints.zh.md)和
[此前的投影优化](2026-10-22-roost-owner-incremental-projection.zh.md)。
独立合成探针中，旧文本为 0/256 KiB/1 MiB 时，Native 追加 p50 分别为
0.178/0.167/0.172 ms，而应用路径从 1.621 增长到 4.770 ms。Native 单独测量不含
收据、索引、控制文档持久化和消费者，只用于定位重复的应用工作，不能作为可达延迟承诺。

初版只优化了 primary 的文本后缀修改和本地目录创建，没有完成复杂操作与恢复状态的
投影复用。本次完成后的消费者在这些路径上遵守同一套语义与持久化约束：

- 共享 reducer 和动作规划器在私有写时复制草稿上记录修改路径，持有新输入并保留
  未修改的存储值。写入验证仍有决定权：路径只用于选择**经过验证的顶层子树**，
  不直接采用 Immer patch 的值。验证可能规范化该字段内的兄弟值，只选择叶子会漏写。
- 精确文本后缀提示避免反复扫描普通追加。真正改写已有文本时仍生成紧凑、按 Unicode
  标量索引的 splice。未闭合的 thinking/plan 块在结束标记完整出现前不运行全文解析，
  有界尾部分析识别跨片段标记。原有解析器、重叠/快照去重、逐事件顺序及坏标量的
  修复或拒绝行为继续共用。
- 私有暂存覆盖 `set`、`remove`、`appendText`、`spliceText`、`spliceArray`，
  同时维护应用值与 SDK 无损表示，只复制修改路径的祖先和新值。新增键遵循 Native
  的规范顺序，自有键检查与 Unicode 标量偏移通过真实 Native 边界核对。
- 只有 Native 元数据、完整事件区间、owner generation 和未变化的窗口均匹配，才安装
  暂存结果。状态层还要求派生索引组实际生效。修改并封存时只读取权威的小型 header/hash。
  不确定结果、外来事件或不支持的转换沿用权威正文读取；最终检查点发布继续验证事件覆盖。
- 恢复后的状态只与最后一个相关追加操作合并；其他修改按受影响字段重建相对 primary
  的差异，保持操作顺序且不无限积累程序。投影按路径复制，不再深复制不可变 primary；
  精确的私有 SDK 快照保留解码值。公开读取和模型摘要仍脱离私有对象。命令借用只发生在
  串行写队列内部，队列外的输入回执查询继续使用正式读取器。

检查点和分支证据由 Roost 持有。每次事务仍原子比较保留的全部检查点证明行；只有
Native 确认没有写入的 stale，才刷新一次。目录转换只证明已确认的本地线性追加成员关系，
不证明旧正文的新鲜度。分叉、远端穿插、不完整页面和不确定结果继续走恢复流程。

本次不修改 Rust/Native 运行时、存储或线协议、签名、保留策略与持久化保证，也不增加
兼容读取器、迁移、发包或部署。这是纯规划/投影工作，不涉及 Effect 生命周期迁移。
如出现无法保持可观察行为或保证的改动，必须停止并讨论。

## 验证与测量边界

[统一验证流程](../../../docs/roost-validation.md)管理准备、所属测试、固定手动负载和
失败处理。持久化基准及配置保存在 `apps/cli/benchmarks`，不进入默认 CI；现在也覆盖
混合标签、工具、计划更新，以及结束/重新打开后继续流式输出。

Linux x64、Node 24.22、2 vCPU；基线 Lody `9f497346a` 与本版均使用
Roost `d4b07d4` 和同一个 Native 二进制。两边都使用 SQLite WAL/FULL、逐动作
控制文档持久化，实时增量读取单独计时。基线/本版按 A–B–B–A 执行；Loro 使用本版
共享语义做一轮参考。下表为各轮 p95 的中位数，单位毫秒。

| 固定负载 / 指标                                   | 补齐前 | 补齐后 |  Loro |
| ------------------------------------------------- | -----: | -----: | ----: |
| 100 轮、2,000 × 256 B 片段：chunk p95             |  11.81 |  11.83 |  4.00 |
| 同上：结束动作 p95                                |  25.49 |  20.44 |  3.98 |
| 单条回复、1,000 × 1 KiB 片段：chunk p95           |  11.58 |  11.81 | 14.19 |
| 10 条回复，每条 100 × 1 KiB，混合/恢复：chunk p95 |  33.09 |  15.15 |  4.94 |
| 同上：最终结束动作 p95                            |  81.76 |  32.38 |  4.94 |

每条 assistant 保留 16 KiB 合成工具结果。混合片段还包含 thinking 标记、Unicode 和
工具/计划更新，每条回复中途结束并重新打开。混合片段写入 CPU 时间从 15.32 降到
7.47 秒；验证前采样的进程峰值 RSS 从 559 降到 515 MiB。RSS 包含运行器和控制层，
不是 Roost 独占内存。普通追加延迟基本不变。混合场景的结束/重新打开组合本身为
98.65 → 104.36 ms（Loro 23.44 ms），不声称这组动作有改善。

多消息/单回复/混合场景的合计数据库大小仍约为 14.39/6.56/8.80 MB，Loro 分别为
2.90/1.54/2.04 MB。本次改善延迟与 CPU，不缩减保留日志体积。冷的旧页/全文读取
成本及固定 SDK/Worker 开销仍在，不据此声称在超长会话或网络场景全面领先 Loro。

45 个写入/重开/分页阶段、完整预期输出、收据重试、跨后端规范业务摘要、重开后的
完整精确摘要和关闭后的 27 项 SQLite 检查全部通过。测量的运行时/基准源码哈希与
本版匹配，研究目录源码与依赖链接全部还原。一次纯准备阶段的尝试把日志放进了要求
为空的数据目录，在测量前即被拒绝；保留其失败和还原记录，不纳入结果。

此前文本追加版本以 Lody `f06b820f3` / Roost `ff1a639` 为基线：增长回复的 chunk
p95 从 26.30 降到 11.98 ms，多消息创建 p95 从 103.01 降到 68.34 ms。
这些数字属于当时的源码组合，不重新标记为本次补齐后的测量。

本次所属检查：CLI 128 项、共享语义/动作 89 项通过。覆盖与既有 reducer 的结果对比、
已测 Unicode/标签/内部标记的逐切分、坏标量、输入所有权、Native 操作结果、规范化的
独立读取与重开结果、收据、分页、分支/owner 边界和恢复状态。混合 Native 用例在写入与
结束期间禁止正文回读，再核对真实存储和重开结果。新增键覆盖自有 `__proto__` 字段，
非法标量偏移被拒绝且不会留下修改。

使用匹配的本地 SDK，Lody 根目录 `corepack pnpm check`、`corepack pnpm format`
和文档检查通过。完整检查保留其报告的可选跳过项，上述所属 217 项没有跳过。最初的
根检查在原有坏标量分支的类型感知 lint 错误处停止；显式类型断言保持运行时的
强制转换/拒绝行为，完整重跑通过。

复用未变化的 SDK/Native 验证：Native 59 项、SDK Chromium/Node 101 项和 WebKit
63 项通过。最初的 SDK 并行尝试触发父级超时，取消的子测试不计为通过。Rust fmt/clippy
通过；整套串行 Rust 测试在未修改的 `rs3_link` 本机回环
`Transport(Unavailable)` 处停止，其单独重跑通过，不将该次尝试称为整套通过。
本次没有改变 SDK/Rust 运行时或 addon 构建输入，复用已记录的二进制和哈希，不重复构建。
